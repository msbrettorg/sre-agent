# T-1.1 — Preserve scheduled task state

## Authorized requirement

Change only the canonical SRE Agent scheduled-task deployment behavior.

- If a scheduled task already exists, preserve its deployed `isEnabled` value during deployment.
- If a scheduled task does not exist, deploy it with `isEnabled: false`.
- Apply equivalent behavior in Bash and PowerShell.

## Explicit scope

- `sreagent-templates/bicep/apply-extras.sh`
- `sreagent-templates/bicep/Apply-Extras.ps1`
- Focused tests for this behavior
- Session plan and Gate evidence

## Change-control prerequisite

- `assets/gates/gsd.json` was added from the canonical schema-v1 GSD definition because Gate could not create this task without it.

## Out of scope

- No Sitecore or Trey deployment or Azure mutation.
- No changes to incident filters, incident platforms, HTTP triggers, or other automation types.
- No changes to scheduled-task prompts, schedules, modes, names, or recipe inventory.
- No unrelated refactoring, commit, or push.
- Any implementation gap stops work for user escalation.

## Acceptance criteria

1. Redeploying an existing enabled scheduled task leaves it enabled.
2. Redeploying an existing disabled scheduled task leaves it disabled.
3. Deploying a scheduled task with no live counterpart sends `isEnabled: false`.
4. Bash and PowerShell implementations remain behaviorally equivalent.
5. Targeted tests pass.
6. Independent scrutiny review reports no scope creep.
